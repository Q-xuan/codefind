# XLSX 局部回读策略评测与选择

## 决定

选定后续范围回读的默认方案：**结构优先，未定位字段列时回退到同行＋表头；固定邻域作为手动备用。** 不根据评测答案决定回退，不把找到候选字段视为已经解释业务含义。

评测原型保留用于对比；选定策略现已接入 `codefind read --anchor ... --field ...`，默认使用 adaptive，并提供显式 range、window、row_headers 和 structure。Go 回归覆盖本文的 8 种合成布局。生产接口报告候选字段、回退原因、有限读取范围与截断状态，不把候选关联当成业务结论。

## 可复现方法

```sh
python tools/eval_xlsx_context.py --self-test
```

公开脚本仅包含使用 Python 标准库的合成评测。真实工作簿、名称、字段坐标映射和专用读取逻辑不分发；下方真实评测仅保留匿名汇总，不能通过公开样例独立复现。

## 策略定义

四种策略使用同样的起点单元格与用户提供的字段别名（参数1 / param1），输出上限均为 96 项原始值或批注。读取合并区域时保留实际存储值的左上角位置。

| 策略 | 规则 |
| --- | --- |
| 固定邻域 | 命中行上下各 2 行、左右各 4 列，包含选中单元格的批注 |
| 同行＋表头 | 先取命中行前 64 列，再取工作表前 12 行前 64 列，去重并裁剪输出 |
| 结构优先 | 命中行前 64 列内寻找相同键值作为候选区块；在每个键右侧向上最多 32 行寻找精确字段别名，返回键、全部候选表头、交叉单元格及批注 |
| 组合默认 | 结构策略定位到字段列时采用其输出，否则回退同行＋表头；无需知道正确答案 |

结构策略不声称同名键一定关联，不在多个同名字段中自动选一个。扫描坐标、源位置与业务关系是不同概念。

## 数据集和判分

- 真实样例 3 个：同一 common 工作表里的 三个匿名配置项 参数1。已独立回读确认值区和备注区的重复键、字段表头与对应原始单元格。这三例共享同一种布局，不算三种独立表型。
- 合成样例 8 个：附近批注、远处平行备注、下移表头、合并表头、同名字段歧义、跨表说明、字段位于键左侧、非结构化同行备注。
- 每例先固定必要证据坐标，再执行策略。覆盖全部必要坐标记为完整覆盖；这不是语义理解准确率。
- `non_gold` 只是未列入必要证据的返回项，不应全部称为噪声，其中可能包括有用的键和字段别名。
- 返回项和字符量衡量上下文体积；访问坐标数衡量内存选择工作量，不等于磁盘 I/O。组合回退的访问数累计两阶段访问，可能重复。

## 观测结果

| 策略 | 真实完整覆盖 | 真实平均返回项 | 合成完整覆盖 | 合成平均返回项 |
| --- | --- | --- | --- | --- |
| 固定邻域 | 0/3 | 30 | 1/8 | 2.75 |
| 同行＋表头 | 3/3 | 96（均截断） | 6/8 | 4 |
| 结构优先 | 3/3 | 10 | 5/8 | 3.5 |
| 组合默认 | 3/3 | 10 | 7/8 | 4.125 |

真实样例中，结构/组合策略平均访问 1126 个坐标，同行＋表头为 832，固定邻域为 40。因此结构策略降低的是返回上下文，不是保证读取工作量更少。在本次 匿名样例中返回文字为 45 字符，同行＋表头为 484 字符，固定邻域为 114 字符但漏证据；未计 JSON 与坐标开销，不能宣称等比例节省 tokens。

单次真实工作簿加载约 193ms，内存策略选择在毫秒以内；脚本每种策略重复选择 30 次并报告均值，均不包含工作簿加载。不要将这些数值外推为正式 Go CLI 的耗时或冷启动性能。

## 失败边界和后续实现条件

- 跨表说明样例全部策略均不完整：局部回读后需继续在工作簿其他表或文档中搜，不能报告说明不存在。
- 固定 64 列、上方 32 行等是原型边界；超界、截断和字段歧义必须在生产接口中显式报告。
- 结构策略定位到一个字段列，不代表已拿齐说明，也可能存在未识别的左侧区块。组合方案不是完整性的保证。
- 合并表头覆盖的是简单样例，尚未验证复杂多级表头、竖排参数和多表混排；需要新增真实工作簿再扩展。
- 首次实现应先提供有预算的单工作簿/工作表/范围回读原语，保留值、批注、合并范围、位置和截断信息。再接入此默认选择器，不引入字段语义推断。
- 固定邻域适合人工指定局部浏览；同行＋表头作为失败回退。没有理由删掉这些备用策略。

选型结论只适用于当前样例和有限读取规则；未与向量、Graph、OCR 或其他产品做性能/准确率对比。
